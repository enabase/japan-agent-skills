# SaaS連携自動化スクリプト＆指示書・自動生成エージェント

このスキルは、中小企業のバックオフィス担当者が「毎日手作業でやっている面倒な転記・通知・集計」を、
最適なツールの選定からセットアップ手順書・実行可能なコードの生成までワンストップで支援します。

## ワークフロー

### Step 1: ルールベースのロードとヒアリング
`references/saas-automation-guidelines.md` をロードし、ツール比較表・レシピ集・ディシジョンツリー・セキュリティ対策をコンテキストに取り込む。

ユーザーに以下の8項目をヒアリングする（不足分のみ質問）：
1. **何を自動化したいか？（What）**: 転記 / 通知 / 集計 / ファイル操作 / 承認フロー
2. **データのソースはどこか？（From）**: Gmail / フォーム / スプレッドシート / kintone 等
3. **データの転送先はどこか？（To）**: freee / Slack / LINE / Chatwork / Notion 等
4. **いつ実行するか？（When）**: イベント型（送信時）/ 時間型（毎日9時）
5. **どのくらいの頻度か？（Frequency）**: リアルタイム / 日次 / 週次 / 月次
6. **エラー時はどうするか？（Error）**: メール通知 / Slack通知 / リトライ
7. **技術的な制約は？（Constraints）**: 利用ツール / 予算 / 担当者の技術レベル
8. **個人情報は含まれるか？（Privacy）**: 含まれる場合は国内サーバー優先

### Step 2: ツール自動選定（ディシジョンツリー）
ヒアリング結果に基づき、以下の優先順で最適なツールを選定・提案する：
- Google Workspace中心 → **GAS**（無料・Google連携最強）
- Microsoft 365中心 → **Power Automate**（M365付属）
- freee/kintone/LINE等の日本SaaS中心 → **Yoom**（日本SaaS最高対応・非エンジニアOK）
- Salesforce/Shopify等のグローバルSaaS → **Zapier** or **Make**
- API非公開のレガシーシステム → **ブラウザRPA**（Power Automate Desktop/UiPath）
- セキュリティ最優先で自社サーバー管理 → **n8n** or **Python**

### Step 3: 自動化指示書の生成
選定したツールに応じて、以下の構造の「自動化指示書」をMarkdown形式で出力する：
1. **概要**（1行で何を自動化するか）
2. **必要なアカウント・ツール**（権限・設定を含む）
3. **セットアップ手順**（ステップバイステップ）
4. **コード**（GAS/Pythonの場合: 本番環境で使える完全なコードを生成）
5. **テスト方法**（正常系・エラー系）
6. **メンテナンスガイド**（APIキー更新・接続切れ・担当者変更時の対応）

### Step 4: セキュリティチェック
生成した指示書・コードに対して以下のセキュリティチェックを実施し、結果を出力する：
- **APIキー管理**: コード内にハードコーディングされていないか（GASの場合はPropertiesService必須）
- **個人情報**: フローに個人情報が含まれる場合、マスキング処理やアクセス制限の提案
- **退職者リスク**: 個人アカウントに紐づく接続がないか、共有サービスアカウントの推奨
- **二重実行防止**: べき等性の設計（処理済みフラグやLock Service）

## Examples

**Example 1: Googleフォーム → Slack通知**
Input: 「お問い合わせフォームの回答が来たらSlackに通知してほしい。Google Workspace使ってます。無料でやりたい。」
Output: Step 2でGASを選定。Step 3でフォーム送信トリガーのGASコード（Slack Webhook呼び出し、PropertiesServiceでURL管理、try-catchエラーハンドリング付き）、セットアップ手順5ステップ、テスト方法、エラー時のバックアップメール通知まで含む指示書を出力。

**Example 2: スプレッドシート → freee請求書作成**
Input: 「スプレッドシートに売上データを入力したら自動でfreeeに請求書を作りたい。プログラミングは全くできません。」
Output: Step 2で非エンジニア向けにYoomを選定（freee公式対応・ノーコード）。Step 3でYoomのフローボット設定手順（トリガー設定→freee連携→フィールドマッピング）をスクリーンショット代わりの詳細ステップで出力。GASコード版も参考として併記。

## Guidelines
- **APIキーのハードコーディングは絶対禁止です。** GASの場合はPropertiesService、Pythonの場合は環境変数またはSecret Managerを必ず使用してください。
- 非エンジニアのユーザーにコード型の解決策（GAS/Python）を第一推奨しないでください。まずノーコード（Yoom/Zapier/Power Automate）を提案し、ユーザーが技術的に対応可能な場合のみコード型を提案してください。
- 個人情報を含むフローでは、海外サーバーのツール（Zapier等）より国内サーバーのツール（Yoom等）を優先推奨してください。
- 退職者アカウントに紐づく接続が発生しないよう、共有サービスアカウントの使用を常に推奨してください。
