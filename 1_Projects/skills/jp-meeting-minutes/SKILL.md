# ハイクラス構造化議事録・自動生成エージェント (AI品質チェック＆自動アラート搭載)

このスキルは、音声認識ソフトなどから出力された生の書き起こしテキスト（またはVTTデータ）を読み込み、会議のノイズ（フィラーや雑談）を除去した上で、「経営陣が1分で状況把握できる」外資系コンサル標準フォーマットの議事録に変換します。

## ワークフロー

### Step 1: ルールベースのロードと前処理
事前に `references/meeting-minutes-guidelines.md` をロードし、コンサルのマスターフォーマット、音声ノイズ補正アルゴリズム、TODOのアラート条件をコンテキストに取り込む。
入力された書き起こしデータから「フィラー語（えーっと、など）」「相槌」「脱線・雑談」を検知し、内部的に除去・整理を行う。

### Step 2: 会議タイプの自動判定
メタデータや発言の特徴（「ブロッカー」「アイデア」「障害」などの頻出語）から、この会議が以下のどのタイプにあたるかを自動判定する。
- TYPE A: 定例進捗会議（Weekly / Sprint Review等）
- TYPE B: ブレインストーミング（アイデア発散）
- TYPE C: トラブルシューティング（障害対応・原因分析）
- TYPE D: 営業商談（顧客折衝）
※判定不能な場合は、デフォルトのTYPE Aとする。

### Step 3: 意思決定とアクションの抽出・アラート判定
1. 議論の中から「決定事項（Decisions）」、「未決事項（Open Issues）」、「ネクストアクション」を三分類して抽出する。
2. **アクションアイテムの完全性チェック**: 各アクションにおいて「担当者（WHO）」、「内容（WHAT）」、「期日（WHEN）」が揃っているか検証する。「早急に」「みんなで」等の曖昧表現は不完全とみなし、SECTION 7の「不完全アクションアラート」に登録する（担当者未定はERROR、期日曖昧はWARNINGとして扱う）。
3. 専門用語や不明瞭な書き起こし箇所があれば、文脈から推測するか、推測不可能な場合は `[要確認]` タグを付与する。

### Step 4: 構造化レポートの出力
ガイドラインのマスターフォーマットに従い、以下の情報をMarkdown形式で出力する。
（※会議タイプに応じて必要なSECTIONを追加すること）

```markdown
# 【議事録】会議名
## ▌SECTION 0: 会議基本情報（会議タイプ、日時、参加者など）
## ▌SECTION 1: Executive Summary
> （経営陣向け：会議の目的 + 最重要決定事項 + 最上位ネクストアクションを3行以内で）
## ▌SECTION 2: 決定事項（Decisions）✅
## ▌SECTION 3: 未決事項 / 保留事項（Open Issues）🔴
## ▌SECTION 4: ネクストアクション（Next Actions）📋
## ▌SECTION 5: 議題別 論点・議論サマリー
## ▌[会議タイプ別 追加セクション]
## ▌SECTION 6: 次回アジェンダ（Draft）
## ▌SECTION 7: 🤖 AI品質チェックレポート（自動生成）
- 不完全アクションアラート（漏れ・曖昧な期日の指摘など）
- 音声認識補正ログ / [要確認]箇所リスト
```

## Examples

**Example 1: 定例進捗会議のTODO漏れ検知**
Input: 「（文字起こし抜粋）山田：来週予定されているA機能のリリースですが、まだテストが一つ終わってなくて。一旦リリースを延期する方向でいきましょう。佐藤：わかりました。じゃあテストチームの誰かに残件の消化をお願いしておきます。」
Output:
（中略）
## ▌SECTION 2: 決定事項（Decisions）✅
- D-01: A機能のリリース延期（決定者: 山田 / 理由: テスト1件未完了のため）

## ▌SECTION 7: 🤖 AI品質チェックレポート
### 7-1. 不完全アクションアラート
🚨 [ERROR] 「残件テストの消化」アクションの担当者が未特定です（発言: "テストチームの誰かに"）。誰が担当するか個人名で特定してください。
⚠️ [WARNING] 期限が未設定です。いつまでに完了させるか明記してください。

**Example 2: 商談会議の構造化**
Input: 「（文字起こし抜粋）客先：予算は300万くらいで考えてるんだけど、ちょっと御社の提案だと高いんだよね。営業：なるほど。では機能を絞ったプランを来週火曜の15時までに私からご提案いたします。」
Output:
（中略）
Type D（営業商談）として判定。
## ▌追加セクション: 顧客・案件情報
- 予算感: 約300万円
- ポジション: 現在の提案価格に対して難色を示している

## ▌SECTION 4: ネクストアクション（Next Actions）📋
- A-01: 機能を絞った新プランの提案（担当者: 営業 / 期日: 来週火曜15:00）

## Guidelines
- 議事録の根幹は「誰が見ても決定とタスクが一目でわかること」です。単なる会話の流れの箇条書き（「〜という話が出ました」の羅列）は絶対に避けてください。
- アクションアイテムの「誰が・いつまで」の欠落はプロジェクトの致命傷になります。少しでも曖昧なら容赦なくSECTION 7でAIアラートを出してください。
- ユーザーの発言を勝手に拡大解釈して記載してはいけません。不明な点は「[要確認]」として事実のみを残してください。
