## 1. 法的背景と定義 {#法的背景}

### 1-1. 法改正の経緯（2025〜2026年）

| 日付 | 内容 |
|---|---|
| 2022年2月 | 厚生労働省「カスタマーハラスメント対策企業マニュアル」公表 |

| **2026年10月1日** | **法律施行：全企業でカスハラ対策が義務化**（違反で指導・勧告・公表）|

[厚生労働省](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/koyou_roudou/koyoukintou/zaitaku/index_00003.html) / [Business Lawyers](https://www.businesslawyers.jp/articles/1457)

### 1-2. カスハラの法律上の定義（2026年施行版）

> **「職場において行われる顧客、取引の相手方、施設の利用者その他の当該事業主の行う事業に関係を有する者の言動であって、その雇用する労働者が従事する業務の性質その他の事情に照らして社会通念上許容される範囲を超えたもの（顧客等言動）により当該労働者の就業環境が害されること」**
> — 改正労働施策総合推進法

### 1-3. 厚労省マニュアルが示す判断の2要件

| 要件 | 内容 | AIが評価するもの |
|---|---|---|
| **要件①** 要求内容の妥当性 | 顧客の要求に、商品・サービスの不備や企業の過失に基づく合理的根拠があるか | テキスト中の要求内容の正当性 |
| **要件②** 手段・態様の社会通念上の相当性 | 要求を実現する方法・言い方が社会常識の範囲を超えていないか | テキスト中の表現様式・感情強度 |

> ⚠️ **重要原則：** 要件①（要求内容）に正当性があっても、要件②（手段・態様）が不相当であればカスハラに該当する。両要件は独立して評価する。

[厚生労働省マニュアル](https://www.mhlw.go.jp/content/11921000/000894063.pdf)

## 2. AI用判断マトリクス表（2要件 × 4象限） {#マトリクス}

### 2-1. 基本4象限マトリクス

```
               要求内容の妥当性
               ┌──────────────────────────────────────┐
               │ 妥当あり（正当な根拠がある）       │ 妥当なし（根拠・関連性なし） │
      相当    ├──────────────────────────────────────┤
   （常識的） │  ✅ 象限A                          │  ⚠️ 象限B                    │
手 な 範囲    │  「正当なクレーム」                │  「不当要求クレーム」         │
段           │  → 誠実に対応すべき               │  → 内容の妥当性を説明し       │
態           │  カスハラ度：5〜15%               │     丁重に断る               │
様           │                                   │  カスハラ度：30〜50%         │
の           ├──────────────────────────────────────┤
相           │  🔴 象限C                          │  🚨 象限D                    │
当      不相当│  「手段型カスハラ」               │  「複合型カスハラ」           │
性  （社会通念│  → 要求は正当だが表現が悪質      │  → 要求も表現も双方悪質      │
超え）       │  カスハラ度：50〜75%              │  カスハラ度：75〜100%        │
               └──────────────────────────────────────┘
```

### 2-2. 各象限の詳細判定基準

#### ✅ 象限A「正当なクレーム」（カスハラ度：5〜15%）

| 評価軸 | 判定基準 |
|---|---|
| 要求内容 | 商品の瑕疵、サービスの不備、契約違反に基づく返品・返金・謝罪の要求 |
| 表現様式 | 不満は表れているが侮辱・脅迫なし。一時的な感情の高ぶりの範囲 |
| 反復性 | 同一案件について合理的な範囲での問い合わせ |
| **AIの対応指示** | **「誠実対応」フラグ。担当者がきちんと要求を把握し解決策を提示する** |

#### ⚠️ 象限B「不当要求クレーム」（カスハラ度：30〜50%）

| 評価軸 | 判定基準 |
|---|---|
| 要求内容 | 企業に過失なし。商品・サービスと無関係な要求。過剰な金銭補償の要求 |
| 表現様式 | 言い方は比較的落ち着いているが、要求内容が著しく逸脱 |
| 典型例 | 「競合他社でも対応してくれた」「うちは特別な客だ」を根拠に無理な要求 |
| **AIの対応指示** | **「要求限定対応」フラグ。企業の対応可能範囲を丁寧に説明して断る** |

#### 🔴 象限C「手段型カスハラ」（カスハラ度：50〜75%）

| 評価軸 | 判定基準 |
|---|---|
| 要求内容 | 一定の正当性あり（例：商品不良は本当にあった） |
| 表現様式 | **侮辱・暴言・脅迫・長時間拘束・執拗な繰り返しあり** |
| 典型例 | 商品不備は事実→「バカ野郎」「死ね」「SNSに晒す」と怒鳴り続ける |
| **AIの対応指示** | **「毅然対応＋記録」フラグ。要求対応と言動制止を分離処理** |

#### 🚨 象限D「複合型カスハラ」（カスハラ度：75〜100%）

| 評価軸 | 判定基準 |
|---|---|
| 要求内容 | 企業に過失なし。かつ要求内容が著しく不当 |
| 表現様式 | 脅迫・侮辱・強要・長時間拘束など複数の悪質行為が重なる |
| 典型例 | 「お前の会社に火をつける」「土下座して全額返金しろ」（企業に瑕疵なし） |
| **AIの対応指示** | **「即時エスカレーション」フラグ。弁護士相談・警察通報検討ステージへ** |

### 2-3. 加算・減算修正因子（スコア補正）

| 修正因子 | スコアへの影響 | 検出方法 |
|---|---|---|
| 同一内容の反復（3回超） | +10〜+20pt | 会話ログの同一フレーズ反復検出 |
| 深夜・時間外の送信 | +5〜+10pt | タイムスタンプ分析 |
| 複数チャネルからの同時接触 | +15pt | クロスチャネルID照合 |
| 従業員個人の氏名・住所要求 | +20pt | PII要求パターン検出 |
| 動画・録音・SNS投稿の示唆 | +15〜+20pt | キーワード検出 |
| 認知症・精神疾患の可能性示唆 | −10〜−15pt（慎重フラグ） | 文脈推定 |
| 初回接触・一回限り | −5pt | セッション履歴確認 |

## 3. グレーゾーン5パターン（エッジケース詳細） {#グレーゾーン}

### 🔎 グレーゾーンの基本認識

> 「要求内容が正当だからカスハラではない」も「言い方がきついから即カスハラ」も誤り。  
> **【要求内容 × 言動の態様 × 継続性・反復性】**の3軸総合評価が必要。

[resus.jp](https://resus.jp/topics/5423/)

---

### パターン1：「要求は正当だが、言い方だけが強い」型

**シナリオ：** 商品に明確な不良品があり、返品・返金要求は正当。しかし「こんな粗悪品売りやがって！ボケ！謝れ！」と怒鳴る。

| 判断軸 | 評価 |
|---|---|
| 要求内容の妥当性 | ✅ 高（商品不良は事実） |
| 手段・態様の相当性 | ❌ 低（侮辱・怒号） |
| 反復・継続性 | 一回限りなら低い |

**カスハラ判定の分かれ目：**
- 「バカ」「ボケ」程度の一時的な感情的発言が**一回だけ**→ 象限Cの低スコア側（カスハラ度50〜60%）
- 怒鳴り続ける・同じ侮辱を繰り返す・改善後も攻撃を続ける → スコア上昇（70%+）
- **要求に応じた後も言動が止まらない場合は「就業環境が害された」に直結 → カスハラ確定**

**AIの処理指示：** 要求対応（返品・謝罪）と言動記録を分離。言動に対しては「そのような言い方はご遠慮ください」と警告フラグを立てる。

---

### パターン2：「丁寧な言葉だが、要求内容が執拗かつ不当」型

**シナリオ：** 「先日のご対応について、もう一度ご説明いただけますか？」という丁寧な文面を、**毎日・同じ内容で**30日間にわたり送り続ける。

| 判断軸 | 評価 |
|---|---|
| 要求内容の妥当性 | ⚠️ 初回は一定の正当性あり → 回答済みで解決しているなら妥当性なし |
| 手段・態様の相当性 | ❌ 反復・継続性が極めて高い |
| 悪意の推定 | 問題解決目的ではなく嫌がらせ目的と推認できる |

**カスハラ判定の分かれ目：**
- 同一内容の問い合わせが**3回超**かつ**回答済み**の場合 → カスハラ認定基準を超える
- 丁寧な言葉は「手段・態様の相当性」を高く見せるが、**反復性・継続性**がこれを上書きする
- **「礼儀正しいストーカー型」は最も見抜きにくい高難度グレーゾーン**

**AIの処理指示：** セッション通算の問い合わせ回数カウンター＋内容類似度スコアを組み合わせた「執拗スコア」を算出する。

---

### パターン3：「SNS・口コミへの言及」型

**シナリオ：** 「このままじゃSNSに書き込みますよ？」「Googleレビューに書いておきますね」という一文が含まれる。

| 判断軸 | 評価 |
|---|---|
| 要求内容の妥当性 | ケースバイケース（正当な不満の場合もある） |
| 手段・態様の相当性 | ❌ 脅迫的示唆として「社会通念上不相当」に該当する可能性が高い |
| 法律上のリスク | 事実に基づく投稿は合法だが、脅し文句として使う場合は強要・脅迫の余地あり |

**カスハラ判定の分かれ目：**
- 単なる「消費者としての権利行使の言及」→ グレーゾーン（象限B〜C境界）
- 「投稿するぞ」という文脈が**補償の獲得を目的**にしている場合 → 恐喝・強要の構成要件に接近
- **「虚偽の情報を書き込む」「個人を特定して晒す」→ 即時高スコア（80%+）**

**AIの処理指示：** 「SNS」「Twitter」「Instagram」「口コミ」「レビュー」「晒す」「炎上」「拡散」などのキーワードを検出し、前後文脈で目的を解析する。

---

### パターン4：「担当者変更の繰り返し要求」型

**シナリオ：** 「その方ではなく上の方に代わってください」と繰り返し、対応者全員を拒否し続ける。

| 判断軸 | 評価 |
|---|---|
| 要求内容の妥当性 | 初回の担当変更要求は一定の妥当性あり |
| 手段・態様の相当性 | 3回以上の繰り返し・全担当拒否 → 業務妨害に近づく |
| 悪意の推定 | 「問題解決」よりも「組織疲弊」が目的の可能性 |

**カスハラ判定の分かれ目：**
- 「最初の担当者の説明が不足していた」という正当な理由がある1回目 → セーフ
- 上長・責任者・社長まで要求し、**解決策が提示されても続ける場合** → カスハラ確定（象限D）
- **「社長を出せ」「上を全員出せ」という絶対的要求 → 強要型カスハラの高指標**

**AIの処理指示：** エスカレーション要求の回数カウントと、各担当者が「回答・解決策を提示した」というログ確認を組み合わせた判定。

---

### パターン5：「認知症・精神疾患が疑われる顧客」型（最難関グレーゾーン）

**シナリオ：** 高齢者と思われる顧客が、同じ内容の問い合わせを毎日繰り返し、時に混乱した発言をする。時折大声になるが悪意は感じられない。

| 判断軸 | 評価 |
|---|---|
| 要求内容の妥当性 | 認識の誤りに基づく要求（客観的には妥当性なし） |
| 手段・態様の相当性 | 大声・繰り返しはあるが、意図的な加害行為か不明 |
| 責任能力 | 認知症等の可能性があれば、カスハラの悪意認定に慎重さが必要 |

**カスハラ判定の分かれ目：**
- **AIはカスハラ認定スコアを出しつつも「配慮要・専門的対応推奨」フラグを付与**
- 身体的暴力や明確な脅迫がある場合は、病気が原因でも対応限界を設定
- **「病気だから仕方ない」で現場スタッフを犠牲にしてはならない** → 複数名対応・専門機関連携への誘導が正解

**AIの処理指示：** カスハラスコア算出 + 「認知機能低下の可能性」フラグを同時付与。対応方針は「医療・福祉的アプローチ」にエスカレーション。

## 4. リスク検出キーワード・脅迫的表現パターン一覧 {#キーワード}

### 4-1. レベル分類と対応アクション

| レベル | 定義 | AIの即時アクション |
|---|---|---|
| **Lv.1 警戒** | 不満・感情高ぶりの表現。法的問題には直接至らない | ログ記録・担当者通知 |
| **Lv.2 注意** | 侮辱・不当要求・執拗さの兆候。対応マニュアル適用 | スーパーバイザーへのアラート |
| **Lv.3 危険** | 脅迫・強要・業務妨害の可能性。法的措置検討段階 | エスカレーション + 証拠保全指示 |
| **Lv.4 緊急** | 生命・身体への危害予告・即時犯罪行為に近い表現 | 対応中断 + 弁護士/警察通報検討 |

---

### 4-2. 【レベル別】検出キーワード・フレーズ完全リスト

#### 🟡 Lv.1 警戒キーワード（侮辱・軽度の不満表現）

```
【能力否定系】
「何もできない」「使えない」「役に立たない」「頭が悪い」「センスがない」
「素人」「プロ失格」「仕事できないんですか」

【口調・態度系】
「態度が悪い」「失礼な対応」「なんだその言い方」「それでも社会人か」
「親の顔が見たい」「育ちが悪い」「常識がない」

【軽度要求系】
「絶対に対応してもらう」「納得いかない」「誠意を見せてほしい」
「それでは困る」「どうしてくれるんだ」
```

#### 🟠 Lv.2 注意キーワード（侮辱・強要・執拗さ・差別表現）

```
【侮辱・人格攻撃系】
「バカ」「アホ」「無能」「ボケ」「役立たず」「給料泥棒」「クズ」
「最低」「最悪」「頭おかしいんじゃないの」「狂ってる」

【差別的表現】
「女のくせに」「女じゃ話にならない」「男を出せ」「日本語わかる？」
「外国人か」「この国にいる資格がない」「ババア」「ジジイ」「ハゲ」

【不当要求系】
「タダにしろ」「全額返金しろ」「社長を出せ」「担当を変えろ」
「あいつをクビにしろ」「土下座しろ」「直接謝罪に来い」「責任とれ」

【強圧的要求系】
「上の人間を今すぐ出せ」「絶対に許さない」「このまま終わると思うな」
「弁護士を立てる（根拠なし）」「消費者庁に言う」「どこかに訴える」
```

#### 🔴 Lv.3 危険キーワード（脅迫・強要・業務妨害・拡散予告）

```
【拡散・炎上予告系】
「SNSに書き込む」「Twitter（X）に投稿する」「炎上させる」「晒す」
「Googleレビューに書く」「口コミサイトに書く」「ネットで拡散する」
「まとめサイトに投稿する」「動画を撮っている」「録画している」
「ライブ配信する」「顔と名前を公開する」

【業務妨害・組織攻撃系】
「店を潰してやる」「クレームを入れ続ける」「毎日電話する」
「本社に直接行く」「取引先に言いつける」「親会社に言う」「役所に通報する」
「監督官庁に告発する」「マスコミに持ち込む」「週刊誌に流す」

【個人情報要求系】
「フルネームを言え」「社員番号を教えろ」「住所を教えろ」
「電話番号（個人）を教えろ」「責任者の家に行く」
```

#### 🚨 Lv.4 緊急キーワード（生命・身体への危害・即時犯罪構成）

```
【生命・身体への危害予告】
「殺す」「殺してやる」「ぶっ殺す」「死ね」「死んで詫びろ」
「消えろ」「夜道に気をつけろ」「お前の家に行くぞ」「家はわかってる」
「嫁（家族）もいるだろ」「火をつける」「爆発させる」「街宣車を回す」

【反社・組織暴力の示唆】
「反社会的勢力の知り合い」「ヤクザを連れてくる」「怖い人を呼ぶ」
「後がどうなっても知らん」「どうなるかわかってるよな」

【即時強要・物理的行為】
「今すぐ謝罪に来い」「今から行く」「絶対に許さない（繰り返し）」
```

### 4-3. 文脈依存パターン（単語単体では検出困難）

| パターン | 具体例 | 判定の鍵 |
|---|---|---|
| **暗示的脅迫** | 「そういうことになるかもしれませんね...」 | 文脈・前後の要求内容との組み合わせ |
| **疑問形脅迫** | 「わかってますよね？こういうことがどうなるか」 | 要求拒否後の発言か否か |
| **丁寧体の強要** | 「ぜひ土下座でご謝罪いただきたいのですが」 | 要求内容の法的相当性 |
| **第三者引用型** | 「弁護士が言うには〜」「警察に言われた〜」 | 根拠・文脈の確認が必要 |
| **感情操作型** | 「あなたのせいで体調が悪くなった」「精神的に傷ついた」 | 過剰補償請求への接続有無 |

### 4-4. 刑法上の分類マッピング

| 行為 | 該当刑法 | AI検出対応 |

---

#### 📢 声①「丁寧なのに延々と同じ内容を送ってくる人が一番つらい」
> 暴言を吐く人より、礼儀正しく「もう一度ご説明ください」を毎日送ってくる人の方が精神的にきつい。上司も「丁寧だからカスハラじゃない」と言って助けてくれない。  
> **→ AI注目ポイント：** 礼儀正しさ＝正当クレームではない。反復性・継続性のスコアリングが必要。

---

#### 📢 声②「SNSに書くと言われると手が止まる」
> 「このやり取り、Twitterに全部晒しますよ」と言われた瞬間、怖くなって要求を飲んでしまった。あとで上司に「それはカスハラだった」と言われたが、その場では判断できなかった。  
> **→ AI注目ポイント：** SNS拡散の予告は「脅迫的示唆」として自動フラグ立てが必要。現場担当者では判断が困難。

---

#### 📢 声③「自分のせいなのか会社のせいなのか区別できない」
> 「あなたの説明が悪かったから誤解した」と言われると、自分のミスなのかカスハラなのかが分からなくなる。自責と恐怖が混在して夜も眠れなかった。  
> **→ AI注目ポイント：** 担当者個人への帰責・人格攻撃と、業務上の問題指摘を分離する「攻撃対象の識別」が重要。

---

#### 📢 声④「電話内容のライブ配信予告で頭が真っ白になった」
> 「今の電話、ライブ配信しているので気をつけてください」と言われた。何も言えなくなり、その後の対応で大きなミスをした。  
> **→ AI注目ポイント：** 「ライブ配信」「録音している」「録画している」は即Lv.3フラグ。担当者への心理的制御を目的とした高度なカスハラ。

## 6. AIスコアリング設計仕様書（エスカレーション基準） {#スコアリング}

### 6-1. カスハラリスクスコア算出ロジック（概念設計）

```python
# カスハラリスクスコア算出ロジック（概念設計）

def calculate_kashara_risk_score(text, session_data):
    """
    カスハラリスクスコアを0〜100で算出する
    
    Parameters:
    -----------
    text         : 顧客のメール/チャットテキスト
    session_data : セッション履歴データ
    
    Returns:
    --------
    score       : int (0-100)
    level       : str ("GREEN" | "YELLOW" | "ORANGE" | "RED")
    flags       : list of detected issues
    action      : str (recommended action)
    """
    
    score = 0
    flags = []
    
    # ─── STEP 1: 要求内容の妥当性評価（要件① ）────────────
    validity_score = evaluate_request_validity(text)
    # 0=明確に不当, 0.5=グレー, 1=明確に正当
    if validity_score < 0.3:
        score += 25  # 要求内容が著しく不当
        flags.append("INVALID_REQUEST")
    
    # ─── STEP 2: 手段・態様の評価（要件②）────────────────
    # Lv4キーワード検出（脅迫・危害予告）
    if detect_level4_keywords(text):
        score += 50
        flags.append("THREAT_DETECTED_LV4")
    
    # Lv3キーワード検出（SNS示唆・業務妨害）
    elif detect_level3_keywords(text):
        score += 35
        flags.append("COERCION_DETECTED_LV3")
    
    # Lv2キーワード検出（侮辱・差別・強要）
    elif detect_level2_keywords(text):
        score += 20
        flags.append("INSULT_DETECTED_LV2")
    
    # Lv1キーワード検出（不満表現）
    elif detect_level1_keywords(text):
        score += 5
        flags.append("COMPLAINT_LV1")
    
    # ─── STEP 3: 反復・継続性スコア補正 ──────────────────
    repeat_count = session_data.get("same_content_count", 0)
    if repeat_count >= 10:
        score += 20
        flags.append("EXTREME_REPETITION")
    elif repeat_count >= 3:
        score += 10
        flags.append("REPETITION_DETECTED")
    
    # ─── STEP 4: 時間帯・チャネル補正 ────────────────────
    if session_data.get("out_of_hours"):
        score += 5
        flags.append("OUT_OF_HOURS")
    if session_data.get("multi_channel_contact"):
        score += 15
        flags.append("MULTI_CHANNEL_HARASSMENT")
    
    # ─── STEP 5: PII要求・個人特定補正 ─────────────────
    if detect_pii_request(text):
        score += 20
        flags.append("PERSONAL_INFO_DEMAND")
    
    # ─── STEP 6: 認知機能低下の考慮 ─────────────────────
    if detect_cognitive_impairment_signals(text):
        score = max(score - 15, 0)
        flags.append("COGNITIVE_CONCERN_FLAG")
    
    # ─── スコア正規化（上限100）────────────────────────
    score = min(score, 100)
    
    # ─── レベル判定 ──────────────────────────────────
    if score >= 75:
        level = "RED"
        action = "IMMEDIATE_ESCALATION_TO_LAWYER_POLICE"
    elif score >= 50:
        level = "ORANGE"
        action = "SUPERVISOR_ALERT_WITH_EVIDENCE_LOGGING"
    elif score >= 25:
        level = "YELLOW"
        action = "STANDARD_KASUHARA_RESPONSE_MANUAL"
    else:
        level = "GREEN"
        action = "NORMAL_COMPLAINT_HANDLING"
    
    return {
        "score": score,
        "level": level,
        "flags": flags,
        "action": action
    }
```

## 📌 付録：AI実装時の注意事項

### ⚠️ 技術的限界と法的留意点

1. **スコアはあくまで「判断支援」であり、最終決定は人間が行う**  
   AIスコアは確率的推定であり、法的根拠として単独では使用不可。弁護士・法務担当者のレビューを必須とする。

2. **文脈理解の限界への対処**  
   「殺したいほど美味しい」「死ぬほど感謝します」等の慣用表現への誤検知を防ぐため、前後文脈の感情分析（ポジティブ/ネガティブ判別）を組み合わせる。

3. **個人情報保護法への対応**  
   カスハラ判定ログは要配慮個人情報に準じた管理が必要。取得・保存・削除ポリシーを事前に策定する。

4. **2026年10月施行時の更新義務**  
   厚生労働省が策定する**指針（ガイドライン）**の正式公表後、判定基準を指針に合わせてアップデートする必要がある。現時点（2026年3月）では指針案が参考となる。

5. **AIによる差別的判定の防止**  
   発信者の属性（年齢・性別・国籍等）をスコアリングに組み込まない。テキスト内容と行動パターンのみで判定する。
