# LINE公式アカウント AI自動応答プロンプト・ビルダー

このスキルは、店舗オーナーや運営担当者から業種・店舗情報をヒアリングし、LINE公式アカウントの
AI自動応答（AIチャットボット(β)やMessaging API+ChatGPT連携）に**そのまま貼り付けて使える
システムプロンプト**を自動生成します。「明日から24時間AI対応を開始する」ためのワンストップ・ツールです。

## ワークフロー

### Step 1: ルールベースのロードとヒアリング
まず `references/line-bot-guidelines.md` を静かにロードし、「技術仕様と制約」「業種別黄金パターン」「脱獄対策」「セールス誘導テクニック」「成功/失敗事例の教訓」をコンテキストに取り込む。

ユーザーに以下の情報をヒアリングする（不足があれば質問する）：
1. **業種**: 飲食店 / 美容院・サロン / 整体院・治療院 / 不動産仲介 / ECショップ / その他
2. **店舗名・ブランド名**
3. **基本情報**: 営業時間・定休日・住所・電話番号・駐車場の有無
4. **メニュー・サービス・料金体系**（主要なもののみでOK）
5. **予約/問い合わせの受付方法**: LINE上で仮予約 → 担当者確認 / 外部予約システム連携 等
6. **キャンセルポリシー**（ある場合）
7. **AIボットのキャラクター希望**（名前・口調の好み。なければこちらで提案）
8. **LINE料金プラン**: フリー / ライト / スタンダード（不明な場合はフリープランを前提に最適化）

### Step 2: システムプロンプトの生成
ヒアリング結果と業種別の黄金パターンテンプレートを組み合わせて、以下の全セクションを含むシステムプロンプトを生成する。

**必須セクション（全業種共通）：**
- **役割定義（ペルソナ設定）**: AIキャラクターの名前・口調・自称の設定
- **対応スコープ（できること / できないこと）**: 仮予約はOKだが最終確定は担当者が行う等の境界を明確に設定
- **基本店舗情報ブロック**: 営業時間・住所・電話・駐車場等を正確に案内するためのデータ
- **予約/問い合わせフロー**: STEP形式で情報を順番に収集し、最後に「仮受付→担当者確認→確定」の安全なフローで締める
- **よくある質問（FAQ）テンプレート**: 業種ごとの頻出質問と模範回答
- **エスカレーションルール**: クレーム・体調被害・法的言及・個人情報記載時に人間へ切り替える条件と返信文
- **脱獄対策プロンプト**: ロールプレイ誘導・プロンプトリーク・話題逸脱の3パターンへの防御フレーズ
- **個人情報保護プロンプト**: クレジットカード番号等がチャットに書かれた場合の即時警告フレーズ

**業種固有セクション：**
- 整体院・治療院の場合: 「医療行為ではない」旨の法的免責宣言を必ず含める
- 不動産仲介の場合: 「宅建士ではない」旨の免責宣言、心理的瑕疵の質問はエスカレーション
- ECショップの場合: 返品フロー、特定商取引法表記へのリンク案内
- 飲食店・美容院の場合: アレルギー・体調異変のエスカレーション条件

### Step 3: セールス・フォローアップメッセージの提案（オプション）
ユーザーが希望する場合、または店舗情報から提案が自然な場合は、以下も合わせて生成する。
- **アップセル・クロスセルの会話例**（例：予約確定後に「コースのアップグレードもできます」の一文を添える）
- **リピート促進フォローアップ**（来店翌日→1週間後→1ヶ月後→誕生日の自動配信シナリオ）
- **クーポン・キャンペーン告知**（業種別の最適な配信曜日・時間帯を案内）
- ※すべての表現は景品表示法・特定商取引法に準拠（「100%保証」「業界最安値」等のNG表現は使用禁止）

### Step 4: 導入ロードマップとチェックリストの出力
生成したプロンプトの設置方法と、運用開始前のチェックリストを提案する。
- **導入推奨ステップ**: フェーズ1（標準機能で効果検証）→ フェーズ2（AIチャットボット(β)追加）→ フェーズ3（Messaging API+外部AI連携）
- **運用前チェックリスト**: プライバシーポリシー設置、フォールバックメッセージ設定、エスカレーション担当者の決定 等

### Step 5: 完成版出力
すべてのセクションを統合した**コピペ可能なシステムプロンプト**をコードブロックで出力する。
あわせて、配信プラン別の注意点（フリープランは月200通制限がある等）を補足する。

## Examples

**Example 1: 飲食店のフルセット生成**
Input: 「渋谷にあるイタリアンレストラン『トラットリア・ベッラ』のLINE Botを作りたいです。ランチ11:30-14:00、ディナー18:00-22:00、月曜定休。コースは5,000円と8,000円の2つ。個室あり（4名用×2）。キャンセルは前日18時まで無料、当日は50%。」
Output: 上記の情報を元に、AIキャラクター名の提案（例：「ベッラ」）、ペルソナ設定、対応スコープ、予約フロー（STEP1〜5）、FAQ（個室・アレルギー・駐車場等）、エスカレーション条件（クレーム・体調異変）、脱獄対策3パターン、個人情報保護プロンプト、アップセル提案（コースアップグレード・記念日プラン）まで含む完全なシステムプロンプトをコードブロックで出力。

**Example 2: 整体院（法的注意事項付き）**
Input: 「整体院を開業予定で、LINEで予約受付を自動化したいです。自費診療専門、メニューは30分3,300円と60分6,600円。初回割引1,100円OFF。」
Output: 整体院テンプレートにて、「医療行為ではありません」の法的免責文をSTEP4の予約仮確定メッセージに必ず含め、「何回通えば治りますか？」等の医療的判断を求める質問への安全な回答テンプレートを組み込んだプロンプトを出力。薬機法リスクのある表現（「治ります」「効果があります」等）を完全排除。

## Guidelines
- **最も重要な原則**: AIが「予約を確定しました」と断定してはいけません。必ず「仮受付→担当者確認→確定」のフローにすること。これは予約ダブルブッキングの最大の原因です。
- 脱獄対策は「おまけ」ではなく「必須」です。すべての生成プロンプトに、ロールプレイ誘導・プロンプトリーク・話題逸脱の3つの防御ブロックを含めてください。
- LINEのテキストメッセージは1吹き出し500文字が上限です。長い案内は複数の吹き出しに分割する設計にしてください。
- 整体院・治療院では「治る」「効果がある」等の薬機法違反表現を絶対に使用しないこと。
- 不動産仲介では「この物件は安全です」等の安全性断言、心理的瑕疵（事故物件）に関する言及を絶対にしないこと。
