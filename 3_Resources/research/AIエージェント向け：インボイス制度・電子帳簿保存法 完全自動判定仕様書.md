## 1️⃣ 適格請求書 必須記載事項（完全版）とAI検出ロジック {#1}

### 【法定6項目一覧：適格請求書（標準インボイス）】

[国税庁](https://www.nta.go.jp/taxes/shiraberu/zeimokubetsu/shohi/keigenzeiritsu/invoice_about.htm) が定める標準インボイスの必須記載事項は以下の6項目です。

| # | 必須記載項目 | AI検出キーワード・パターン | チェックポイント | 不備の典型例 |
|---|---|---|---|---|
| ① | **書類交付を受ける事業者の氏名または名称** | 宛名、御中、様、To | 請求書の冒頭・右上に記載が存在するか | 「御担当者様」など個人名のみで社名なし |
| ② | **売手の氏名または名称 ＋ 登録番号** | `T[0-9]{13}`の正規表現で検出 | T＋13桁の数字列が存在するか | 登録番号の記載なし・T＋12桁や14桁などの誤フォーマット |
| ③ | **取引年月日** | `[0-9]{4}[年/\-][0-9]{1,2}[月/\-][0-9]{1,2}[日]?`等 | 実際の取引日（請求日ではなく取引が行われた日付） | 請求日のみで取引日なし・和暦と西暦の混在で判読不能 |
| ④ | **取引内容（軽減税率対象品目の旨）** | ☆、※、〇等の識別記号＋「軽減税率対象」等の文言 | 8%品目が含まれる場合、軽減税率対象の旨が明示されているか | 8%品目があるのに軽減税率の識別マーク・注記が一切ない |
| ⑤ | **税率ごとの対価の合計額（税抜または税込）＋ 適用税率** | 10%、8%、消費税率、税抜合計、税込合計 | 8%・10%それぞれの課税対象合計が区分されているか | 合計金額のみで税率別内訳なし |
| ⑥ | **税率ごとに区分した消費税額等** | 消費税額、消費税、内税、外税 + 税率の組み合わせ | 8%分・10%分それぞれの消費税額が明記されているか | 消費税の総額のみ記載（8%・10%の内訳消費税額なし） |

### 【登録番号（T番号）の形式・AI検証ロジック】

[国税庁 公表サイト](https://www.invoice-kohyo.nta.go.jp/about-toroku/index.html) より

```
正規表現パターン（第一段階：形式チェック）:
  ^T[0-9]{13}$

法人の場合  : T + 法人番号13桁（法人番号と一致）
個人事業主の場合: T + マイナンバーとは別の13桁固有番号
```

#### 📌 AI登録番号検証の3ステップ

```
STEP 1【形式チェック】
  → 正規表現 ^T[0-9]{13}$ に一致するか
  → 一致しない場合：「登録番号フォーマット不正」を即フラグ

STEP 2【チェックディジット検証（法人の場合）】
  → T除く13桁の先頭1桁が法人番号と同じ構造か確認
  → 法人番号の場合はチェックディジット検算が可能

STEP 3【国税庁公表サイトAPIとの突合（推奨）】
  エンドポイント: https://www.invoice-kohyo.nta.go.jp/
  → 登録番号が有効（失効・取消でない）かをリアルタイム確認
  → 取引日時点での有効性確認が必須
     ⚠️ 登録後に取り消された番号でも形式は正しいため、
        形式チェックだけでは「有効な適格請求書発行事業者」と
        断定できない
```

[note（三和ホールディングス）](https://note.com/mitsuwa_holdings/n/n79a6800fd356) / [Invoice Media](https://media.invoice.ne.jp/column/invoices/invoice-consumption-tax-total-individual-mismatch.html) より

### 【AI計算検証ロジック】

```
■ 正しい計算手順（AIが期待する処理）：
  STEP 1: 8%対象品目の税抜合計を算出
  STEP 2: 8%対象品目の消費税額 = 税抜合計 × 0.08（端数処理は1回のみ）
  STEP 3: 10%対象品目の税抜合計を算出
  STEP 4: 10%対象品目の消費税額 = 税抜合計 × 0.10（端数処理は1回のみ）
  STEP 5: 請求書合計 = 全税抜合計 + 8%消費税額 + 10%消費税額

■ 端数処理方式：切捨て・切上げ・四捨五入 → 任意（ただし自社内で統一必須）
```

### 【AIが最も誤判定しやすい・経理担当者が疲弊するグレーゾーン一覧】

| # | 誤りのパターン | 具体例 | 正しい処理 | AIチェックフラグ |
|---|---|---|---|---|
| **GZ-01** | **明細ごと端数処理の積み上げ計算** | 各行で切捨→合計 → インボイスルール違反 | 税率別合計に対して1回だけ端数処理 | 明細消費税の合算値 ≠ 税率別消費税記載値の場合フラグ |
| **GZ-02** | **1円ズレ問題** | 消費税額の合計と明細積み上げが1〜数円ズレ | 「1円差は計算方式の差」として認識、税率別合計値を正値とする | 差異が±3円以内は「計算方式差異（参考）」として警告に留める |
| **GZ-03** | **税込価格のみ記載で税率不明** | 「合計 110,000円（税込）」のみ | 税抜合計または消費税額と税率の明記が必要 | 税抜金額・消費税額のどちらも検出されない場合フラグ |
| **GZ-04** | **軽減税率品目の識別マーク漏れ** | 食品と文具が混在しているのに☆マークなし | 8%対象品目に明確な識別記号を付与 | 8%・10%混在が推定されるのに識別記号・注記なしの場合フラグ |
| **GZ-05** | **消費税合計しか記載がなく税率別内訳なし** | 「消費税計 10,000円」のみ | 「うち8%対象：○○円」「うち10%対象：○○円」の区分記載 | 税率別消費税額の複数値が検出されない場合フラグ |
| **GZ-06** | **複数書類の端数処理二重計算** | 納品書で端数処理 ＋ 請求書でも端数処理 | 消費税額を記載する書類（どちらか）でのみ1回 | 納品書・請求書両方に消費税額が記載されている場合、組み合わせ確認を促す警告 |
| **GZ-07** | **税率混在請求書で合計消費税を逆算記載** | 合計額から逆算して消費税額を書く | 税率別合計 × 税率で正算する | 逆算値と正算値に差がある場合フラグ（許容差±2円） |
| **GZ-08** | **割引・値引き処理後の消費税未再計算** | 早期払い割引後に消費税を変更せず | 値引き後の税抜合計に対して消費税を再計算 | 値引き後合計と消費税額の整合性チェック |

### 【消費税計算の正誤検証ロジック（AI実装用疑似コード）】

```python
def check_consumption_tax(invoice_data):
    """
    invoice_data = {
        'items': [{'name': str, 'tax_rate': float, 'price_ex_tax': int}],
        'stated_tax_8': int,   # 請求書記載の8%消費税額
        'stated_tax_10': int,  # 請求書記載の10%消費税額
        'rounding_method': 'floor' | 'ceil' | 'round'  # OCRで推定
    }
    """
    total_8 = sum(item['price_ex_tax'] for item in invoice_data['items'] if item['tax_rate'] == 0.08)
    total_10 = sum(item['price_ex_tax'] for item in invoice_data['items'] if item['tax_rate'] == 0.10)
    
    # 正しい消費税額（税率別合計に対して1回計算）
    expected_tax_8 = apply_rounding(total_8 * 0.08, invoice_data['rounding_method'])
    expected_tax_10 = apply_rounding(total_10 * 0.10, invoice_data['rounding_method'])
    
    diff_8 = abs(expected_tax_8 - invoice_data['stated_tax_8'])
    diff_10 = abs(expected_tax_10 - invoice_data['stated_tax_10'])
    
    if diff_8 == 0 and diff_10 == 0:
        return "✅ 消費税計算：正常"
    elif diff_8 <= 3 and diff_10 <= 3:
        return "⚠️ 消費税計算：1円前後の差異（端数処理方式の差の可能性）"
    else:
        return f"❌ 消費税計算：不備（8%差異={diff_8}円, 10%差異={diff_10}円）"
```

### 【AIによる自動ファイルリネーム 推奨命名規則】

#### 🔷 基本フォーマット（電子帳簿保存法準拠）

```
YYYYMMDD_取引先名_金額(税込)_書類種別.pdf

例：
  20261015_株式会社山田商事_110000_請求書.pdf
  20261201_フリーランス田中太郎_55000_請求書.pdf
  20261130_ABC合同会社_330000_領収書.pdf
```

#### 🔷 詳細フォーマット仕様（AI実装用）

| フィールド | フォーマット | 必須 | 取得元OCR項目 | 注意事項 |
|---|---|---|---|---|
| **取引年月日** | `YYYYMMDD` | ✅必須 | 取引日・請求日・発行日 | 和暦→西暦変換が必要な場合あり（令和8年→2026年） |
| **取引先名** | 社名・屋号（最大20文字推奨） | ✅必須 | 発行者名・会社名 | 「株式会社」「（株）」の表記統一、記号・スペース除去 |
| **取引金額** | 税込金額（整数・円） | ✅必須 | 税込合計・ご請求金額 | 税抜か税込かを社内で統一。カンマ除去 |
| **書類種別** | `請求書`/`領収書`/`見積書`/`納品書` | 推奨 | 文書タイトル | AIでタイトル行から自動分類 |

#### 🔷 AIリネーム処理フロー（疑似コード）

```python
def generate_filename(ocr_result, default_doc_type="請求書"):
    """
    OCR抽出データからEDI法準拠のファイル名を生成する
    """
    # 1. 取引年月日の抽出・正規化
    raw_date = ocr_result.get('transaction_date') or ocr_result.get('issue_date')
    normalized_date = normalize_to_yyyymmdd(raw_date)  # 和暦・西暦・スラッシュ区切り等を統一
    
    # 2. 取引先名の正規化
    company_name = ocr_result.get('issuer_name', '不明取引先')
    company_name = company_name.replace('　', '').replace(' ', '').replace('/', '').replace('¥', '')
    company_name = company_name[:20]  # 最大20文字に切り詰め
    
    # 3. 取引金額の抽出（税込合計を優先）
    amount = ocr_result.get('total_amount_inc_tax') or ocr_result.get('total_amount_ex_tax', 0)
    amount_str = str(int(amount)).replace(',', '')
    
    # 4. 書類種別の特定
    doc_type = classify_document_type(ocr_result.get('title', ''))  # 請求書/領収書等
    
    return f"{normalized_date}_{company_name}_{amount_str}_{doc_type}.pdf"

# 出力例：
# 20261015_株式会社山田商事_110000_請求書.pdf
# 20260901_フリーランス田中太郎_55000_請求書.pdf
```
