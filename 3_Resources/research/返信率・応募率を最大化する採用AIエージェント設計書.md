# 第1章：スカウトメールの「開封率・返信率」を左右する要因

## 1-1. 媒体別データ（2024〜2026年最新）

| 媒体 | 平均返信率 | 備考 |
|------|-----------|------|
| **Findy** | **56.9%** | エンジニア特化・圧倒的1位 |
| **ReDesigner** | **50.0%** | デザイナー特化 |
| **Wantedly** | **11〜27%** | 最高値49.3%の企業事例あり |
| **LinkedIn** | **20.0%** | PublicLinkedIn経由 |
| **ビズリーチ** | **6%前後** | 中小×難職種では0.8〜0.9%まで低下 |
| **Green** | **2.2%** | IT特化だが競合激烈 |

## 1-2. 返信率が高いスカウトメールの共通パターン

3つの離脱ポイント設計原則：

```
ステップ1：件名を見て「開封するか」を決める（25文字以内・数字型）
     ↓
ステップ2：冒頭を読んで「その先を読むか」を決める（本人が知らない具体的評価を2行以内）
     ↓
ステップ3：最後まで読んで「返信するか」を決める（コピペQ&A型でハードルをゼロに）
```

## 1-3. NG共通パターン

| NG表現 | 問題点 |
|--------|--------|
| 「貴殿のご経歴を拝見し〜」 | 最悪の定型文 |
| 3000文字超えの長文 | 即スキップ |
| 「正式な選考として面接を〜」 | 心理的ハードル最大 |

## 1-4. 転職潜在層へのアプローチ心理学

| レジュメのシグナル | 推測される不満 | 刺さる訴求 |
|------------------|--------------|-----------|
| IT大手在籍3年以内 | 裁量のなさ・歯車感 | 「0→1フェーズに参加できる」 |
| 年功序列企業10年以上 | 成果が評価されない | 「完全成果主義」 |
| 残業実績なし強調 | WLBへの強いこだわり | 「残業月10h以下・有休95%」 |

# 第2章：媒体別スカウトメール・テンプレート設計

## 2-1. Wantedly（カジュアル・ミッション訴求型）

**件名例：**
```
「◯◯経験を活かして、プロダクトを"作る"側に来ませんか？」
```

**本文テンプレート：**
```
こんにちは、[会社名] の [送信者名]（[役職]）です。

[候補者の実績・スキル（具体的に1点）]という点にすごく注目してメッセージしました。

私たちは今、[ミッション・目指す世界を1文で]というチャレンジをしています。

[ポジション名]として、[裁量の範囲・面白い点を2〜3行]。

まずはZoomで30分、コーヒーでも飲みながら話しませんか？
（選考とか関係なし、気軽に話しましょう！）

[送信者名]
```

## 2-2. ビズリーチ（ハイクラス・年収訴求型）

**件名例：**
```
「想定年収◯◯〜◯◯万円｜[業界]での[役割]ポジション、ご覧ください」
```

**本文テンプレート：**
```
[候補者名]様

■ ポジション：[ポジション名]｜[部門・チーム名]
■ なぜあなたなのか：[候補者のスキル・経験が自社でどう活きるか]
■ 提供できる環境
  ・年収：◯◯〜◯◯万円
  ・裁量：[意思決定の範囲]
  ・働き方：[リモート割合・残業実態]
```

## 2-3. Green（IT/Web特化・技術訴求型）

**件名例：**
```
「[技術スタック]×[業務領域]の両方で動ける環境、あります」
```

**本文テンプレート：**
```
・技術スタック：[具体的な言語・フレームワーク・インフラ]
・開発スタイル：[アジャイル/スクラム等・CI/CD有無]

「現在の開発環境について、一言教えてください」
（コピペで返信いただけるだけでOKです）
```

## 2-4. LinkedIn（日英バイリンガル対応）

**件名例：**
```
「[役割] Opportunity at [会社名] — [候補者の強みに関連するキーワード]」
```

**本文（英語パート）：**
```
What we offer:
- [Key benefit 1]
- [Key benefit 2]

Would you be open to a brief call? No pressure — just a conversation.
```

## 2-5. リクナビNEXT / doda（幅広い職種対応）

**件名例：**
```
「年間休日125日・残業月10時間以下／[職種]での転職をお考えの方へ」
```

**本文テンプレート：**
```
【ポジション概要】
・職種：[職種名]
・チーム：[人数・構成・雰囲気]
・裁量：[意思決定の範囲]

【待遇・環境】
・給与：月給◯◯万円〜◯◯万円
・賞与：年2回（昨年度実績：計◯ヶ月分）
・残業：月平均◯時間（実績値）
```

# 第3章：「刺さる求人票」の構造設計

## 3-1. 求人票の読まれ方分析

**スクロール到達率の目安：**
```
ファーストビュー：100%（全員）
35%地点：80%
50%地点：50%（半数離脱）
最下部：20%以下
```
→ **重要な情報はファーストビューに集中させる**

## 3-2. タイトルのBefore→After

| ❌ Before | ✅ After |
|----------|---------|
| 「事務スタッフ募集」 | 「IT系スタートアップを縁の下で支えるコアメンバー募集」 |
| 「エンジニア募集」 | 「自社開発／TypeScript×Next.js／技術選定に参加できる環境」 |
| 「施工管理（正社員）」 | 「地域密着の建設会社で現場を任される施工管理ポジション」 |

## 3-3. 仕事内容に書くべき5つの要素

```
① 1日の流れ（タイムライン形式）
② 使用ツール・技術スタック
③ チーム構成（人数・平均年齢・雰囲気）
④ 裁量の範囲（具体的な意思決定シーン）
⑤ 入社後の成長パス（3ヶ月・6ヶ月・1年後）
```

## 3-4. NG表現リスト（法令遵守）

| 種別 | NG表現 | 代替表現 |
|------|--------|--------|
| 年齢差別 | 「35歳以下」「若い人が活躍中」 | 「未経験からのキャリアチェンジ歓迎」 |
| 性差別 | 「主婦歓迎」「ママさん活躍中」 | 「育児中のメンバーも活躍（性別不問）」 |
| 障害者差別 | 「体力に自信のある方」 | 「〇kgの運搬業務があります」と具体化 |

## 3-5. 給与の書き方

| ❌ NG | ✅ OK |
|------|------|
| 「給与：要相談」 | 「月給25〜40万円（経験・スキル考慮）」 |
| 「賞与あり」 | 「賞与年2回（2024年度実績：計4.2ヶ月分）」 |

# 第4章：候補者レジュメからの「刺さりポイント」自動抽出ロジック

## 4-1. レジュメから読み取るべき5つの情報

```
① 直近の職種・役割（現在地の確認）
② 転職回数・在籍期間のパターン（転職意欲の推測）
③ スキルセットのギャップ（やりたいけどできていないことの推測）
④ キャリアの方向性（上昇志向／安定志向／専門深化）
⑤ 「裏の退職理由」の推測（残業多い→WLB訴求、年功序列→裁量訴求）
```

## 4-2. AIプロンプト設計例

```
以下の候補者プロフィールを分析してください。

(1) 現在の職場への不満として最も可能性が高い3点を推測
(2) 自社の強みリストの中から最もマッチする3点を選択
(3) {媒体名}向けスカウトメールを{文字数}字以内で生成
(4) 件名パターンを2種類生成
    A：条件訴求型（数字入り）
    B：共感訴求型（候補者の状況に寄り添う）
(5) 送信推奨者を提案

【候補者プロフィール】
{ここにレジュメテキストを貼り付け}
```

## 4-3. 法令遵守の注意事項

| 法令 | 禁止事項 |
|------|--------|
| 個人情報保護法 | レジュメ情報を採用目的以外に利用すること |
| 職業安定法 | 媒体DBを採用目的以外に流用すること |
| 公正採用選考基準 | 人種・宗教・出身地・家族構成を採否の根拠にすること |

# 第5章：採用担当者の生の声と成功・失敗事例

## 5-1. 成功事例

**事例1：建設業中小企業 / ビズリーチ活用**

> Before：返信率 **0.8〜0.9%** → After：同条件平均の約 **3.5倍**

改善ポイント：件名から職種名を削除→年収・年間休日の数字に変更、冒頭の定型文を具体的実績言及に変更、送信者を人事→現場工事部長に変更

**事例2：IT系スタートアップ / Wantedly活用**

> Before：返信率 **5%** → After：**23%**（最高値49.3%）

改善ポイント：CTO自らが熱量のあるメッセージを発信、候補者のGitHubを確認し「〇〇のリポジトリを見ました」と追加

## 5-2. 失敗事例

```
❌ 失敗例1：ChatGPT丸投げスカウト
「貴殿のご経歴を拝見し、弊社の求める人材像に合致すると判断いたしました。」
→ X（旧Twitter）で晒されるリスク

❌ 失敗例2：デザイナーへの「エンジニア募集」メール
→ 「プロフィールを読んでいない」ことが一目瞭然・企業ブランド毀損

❌ 失敗例3：3000文字の長文スカウト
→ 候補者はスクロールして終了。返信率ほぼ0%
```

## 5-3. 中小企業共通の悩みと解決策

| 悩み | 解決策 |
|------|--------|
| 「100通送っても3通しか返信がない」 | 件名・冒頭・クロージングの3要素改善で返信率10倍の差が出る |
| 「求人票を出してもアクセスゼロ」 | タイトルを候補者目線に書き直し、数字を入れる |
| 「知名度がないから見向きもされない」 | 社長・現場メンバーからの直接スカウト＋SNS採用ブランド構築 |

## 5-4. 知名度ゼロの中小企業が勝つ5つの戦略

```
① ナラティブ採用（創業経緯・失敗談をWantedlyストーリーで発信）
② 採用ピッチ資料の整備（スカウトメールに添付できるPDF/Notion）
③ 社長・役員直接スカウト（人事比で返信率2〜3倍）
④ カジュアル面談文化の徹底（「選考ではない・30分・志望動機不要」）
⑤ SNS採用ブランド構築（X・Instagram・TikTokで「知ってる会社」に）
```

## 5-5. 採用コスト比較

| 採用手法 | コスト目安 | 特徴 |
|--------|----------|------|
| 人材紹介（エージェント） | 年収の30〜35% | コスト高・プロが動く |
| ダイレクトスカウト媒体 | 月額30〜100万円 | 自社工数が必要・直接アプローチ |
| 求人媒体掲載（doda等） | 20〜100万円/月 | 幅広い母集団・競合多数 |
| 自社採用サイト | 構築費用のみ | 中長期コスト最安・即効性なし |
| SNS採用 | ほぼ0円 | コスト最安・時間がかかる |

# 第6章：AIエージェントシステム設計仕様

## 6-1. システム全体構成

```
INPUT
 ├── 候補者レジュメ（PDF/テキスト）
 ├── 自社採用要件・JD
 ├── 送信媒体の選択
 ├── 会社の魅力リスト（20〜30点）
 └── 送信者情報

PROCESS
 ├── STEP1：レジュメ解析
 ├── STEP2：5軸分析
 ├── STEP3：魅力リストとマッチング
 ├── STEP4：媒体テンプレート適用
 ├── STEP5：スカウト文生成
 ├── STEP6：件名A/Bパターン生成
 ├── STEP7：人間レビュー用プレビュー
 └── STEP8：送信タイミング最適化

OUTPUT
 ├── スカウトメール本文（媒体対応版）
 ├── 件名2パターン（A/Bテスト用）
 ├── 訴求選定の根拠説明
 ├── 送信推奨者のサジェスト
 └── 送信推奨タイミング
```

## 6-2. 送信タイミングの最適化

| 媒体 | 推奨曜日 | 推奨時間帯 |
|------|--------|---------|
| ビズリーチ | 火・木 | 12〜13時 or 20〜22時 |
| Wantedly | 月・火・水 | 12〜14時 |
| Green | 木・金 | 19〜21時 |
| LinkedIn | 月・火 | 9〜11時 |

## 6-3. PDCAサイクル設計

```
WEEK 1：50通送信
  件名A（条件訴求型）：25通
  件名B（共感訴求型）：25通
     ↓
WEEK 2：データ分析 → 返信率の高い件名を特定 → 改善反映
     ↓
4週間（2ループ）で1セット完了
→ 3ヶ月で返信率を最適化
```

# 付録A：スカウトメール送信前チェックリスト

```
□ 候補者の直近職種・実績に1点以上言及しているか
□ 件名に数字または疑問形が含まれているか
□ 「ご経歴を拝見し〜」等の定型文で始まっていないか
□ 文字数は400〜800文字以内に収まっているか
□ いきなり「面接」を求めていないか
□ 送信者が候補者にとって「会いたい人」設定になっているか
□ 法令上のNG表現（年齢・性別・障害者差別）が含まれていないか
□ 給与・条件の実態数値が記載されているか
□ 返信する理由（コピペQ&A or カジュアル面談誘導）が明確か
□ 署名に人間味のある一言が含まれているか
```

# 付録B：求人票最終チェックリスト

```
□ タイトルに「環境・条件の差別化ポイント」が含まれているか
□ タイトルが35文字以内か
□ 給与に実績値（賞与実績・年収例）が記載されているか
□ 「一日の流れ」「チーム構成」「使用ツール」が記載されているか
□ 入社後の成長パスが書かれているか
□ 年齢・性別・障害者差別のNG表現がないか
□ 固定残業代の時間数が明示されているか
□ 応募ボタンの上に最も刺さる要素が来ているか
```
