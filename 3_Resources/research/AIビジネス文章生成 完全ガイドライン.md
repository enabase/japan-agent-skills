## 1. 【AI特有のNG表現リスト】「ChatGPT構文」全解剖

### 🔴 なぜAIメールはバレるのか？ ── 識別3原則

> 「教科書通りの構成が完璧すぎることが、逆に定型文的な印象を与える。受け取った側が『これはテンプレートだな』と感じる」
> ── [空洞マガジン（ChatGPTとClaudeのビジネスメール比較検証）](https://kuudoochan.com/ai/chatgptclaude/)

| 識別ポイント | AIが陥るパターン | なぜ問題か |
|---|---|---|
| **構成の完璧さ** | 挨拶→謝罪→原因→対策→締め、が必ず揃う | 人間は状況に応じて省略する。省略ゼロ＝ロボット感 |
| **命令的な明確さ** | 結論が前に来すぎて「指示文」に聞こえる | 敬意より効率を優先した印象を与える |
| **敬語の過剰積み** | 二重敬語・過剰敬語が混入する | 「伺わせていただく」系の連鎖が不自然 |

---

### 🚫 ChatGPT構文 NG表現リスト ── カテゴリ別32選

#### ▶ カテゴリA：定型挨拶の連発（冒頭/結び）

| NG表現 | 問題点 | 自然な言い換え |
|---|---|---|
| `平素より大変お世話になっております` | **冒頭に毎回使われる最頻出AI構文**。AIが書いたと一瞬でバレるシグネチャ表現 | `いつもありがとうございます`（関係値に応じて省略も可） |
| `時下ますますご清栄のこととお慶び申し上げます` | 手紙の書き言葉をメールに転用。現代ビジネスでは古風・違和感 | 省略、または`〇〇の件でご連絡申し上げます`と本題に入る |
| `何卒よろしくお願い申し上げます（連呼）` | 1通のメール内に3回以上登場するAI頻出パターン | 文末は1回だけ。変化をつけて`ご確認のほど、よろしくお願いいたします` |
| `引き続きよろしくお願いいたします（毎回）` | 関係を継続したいニュアンスだが、AIが機械的に付けると空虚に | 具体的な次アクションを書く：`次回は〇月に打合せができれば幸いです` |
| `ご査収のほどよろしくお願いいたします` | 添付ファイルなしのメールに誤用されることが多い | 添付がある場合のみ使用。ない場合は`ご確認いただけますと幸いです` |

#### ▶ カテゴリB：接続詞・構造語の乱用

| NG表現 | 問題点 | 自然な言い換え |
|---|---|---|
| `なお、〜` を1通に3回以上使う | AIが複数情報を列挙する際の典型構造。読み手が「また来た」と感じる | 箇条書きに変換するか、段落を分ける |
| `また、〜` の連続使用 | 同上。「また」「なお」「さらに」「加えて」が連鎖するAI構文 | パラグラフを分けて独立させる |
| `つきましては、〜` の多用 | 依頼文の前置きとして多用。毎回登場すると形式的 | `そこで、〜をお願いしたいのですが` と口語的に |
| `上記の件につきまして` | メール冒頭の件名整理に多用されるAI的な冗長表現 | `〇〇の件について` と直接件名を指す |

#### ▶ カテゴリC：過剰敬語・二重敬語

| NG表現 | 問題点 | 自然な言い換え |
|---|---|---|
| `いただければ幸いでございます` | 「〜れば＋幸い＋でございます」の三重敬語。過剰 | `いただけますと助かります` or `ご確認ください` |
| `〜させていただく` の連続（3回以上） | AIが謙譲を重ねる最典型。現代では「自分に都合よく使う敬語」として批判される | 1回使ったら別の謙譲表現に変える。`〜いたします`/`〜申し上げます`で分散 |
| `ご確認いただけましたでしょうか` | 正確な敬語だがAI頻出すぎて不自然感を生む | `ご確認はお済みでしょうか` / `その後いかがでしょうか` |
| `お忙しいところ大変恐縮ではございますが` | 形式的すぎる。本当に申し訳なければもっと具体的な言葉になるはず | `少しお時間をいただけますか` / `急なお願いで恐れ入りますが` |
| `誠に勝手ながら` | 使い方は正しいが、AIが断りや制限事項の前に自動挿入する構文 | 状況を具体的に説明：`弊社の都合により、〜` |

#### ▶ カテゴリD：「直訳メタファー」「英文脈語」の混入

| NG表現 | 問題点 | 自然な言い換え |
|---|---|---|
| `ご共有いただきありがとうございます` | "Thank you for sharing" の直訳。日本語として不自然 | `お知らせいただきありがとうございます` / `教えていただきありがとうございます` |
| `〜についてアップデートします` | "I'll update you" の直訳カタカナ混入 | `〜についてご連絡いたします` / `進捗をご報告いたします` |
| `〜に関してフォローアップいたします` | 同上 | `〜について改めてご連絡いたします` |
| `マイルストーンを達成した際には` | IT/外資系文脈の英語をそのまま使うAI傾向 | `〇〇が完了した際には` / `節目を迎えましたら` |
| `ご認識のずれがございましたら` | "misalignment" 直訳。違和感が強い | `認識に齟齬がある場合は` / `ご不明点がございましたら` |

#### ▶ カテゴリE：感情・温度が「ゼロ」な締め文

| NG表現 | 問題点 | 自然な言い換え |
|---|---|---|
| `ご不明な点がございましたら、お気軽にお問い合わせください` | ヘルプページのコピーそのもの。人間関係を感じさせない | `ご不明な点は何でもおっしゃってください` / 相手の名前を入れる |
| `何卒ご理解ご協力のほどよろしくお願い申し上げます` | お役所文書的。丁寧すぎて冷たい | 具体的な協力内容を書いて締める。`〇〇についてご協力いただけると大変助かります` |
| `以上、よろしくお願いいたします` | 最後の締めが唐突に短い。「以上」はメールの締めに向かない | `お手数をおかけしますが、よろしくお願いいたします` |

#### ▶ カテゴリF：「ChatGPT的優等生すぎる謝罪」

| NG表現 | 問題点 | 自然な言い換え |
|---|---|---|
| `この度は多大なるご迷惑をおかけし、誠に申し訳ございませんでした。今後はこのようなことのないよう再発防止に努めてまいります。` | 完璧すぎる謝罪テンプレ。誠意ゼロに見える | **具体的な原因→再発防止策→今後のアクション** を1行ずつ書く。抽象的な誓いは禁止 |
| `ご不便をおかけし大変申し訳ございません` | 「ご不便」は軽微なトラブルに使う言葉。重大なミスに使うと謝罪が軽く見える | 深刻度に応じて：`多大なるご迷惑`/`ご心配をおかけ`/`重大な問題` を使い分ける |

---

### 💡 AI生成時の「温度・人称コントロール」ルール

```
❌ 感情がゼロ：「本件については、以下の通り対応いたします。」
✅ 温度あり  ：「大変お待たせしてしまい、申し訳ありません。下記の通り進めさせてください。」

❌ 三人称的：「弊社といたしましては、〜と考えております。」（多用）
✅ 一人称的：「私としては、〜と思っております。」（個人の意見・判断を出す）
```

## 2. 【心理的安全性を保つクッション言葉・枕詞マトリクス】

> 「いきなり要望を切り出すのではなく、ワンクッションとなる言葉を入れましょう」
> ── [リクナビNEXT ジャーナル（日本ビジネスメール協会 平野友朗氏）](https://next.rikunabi.com/journal/20150910/)

### 設計原則：「高さの制御」

コミュニケーションの「高さ」──伝え手と受け手の意識上の上下関係を誤ると、「見下したような感じ」と受け取られる。AIが生成する際は常に **「同じ目線、または相手を上に置く」** 姿勢を基本とすること。([東洋経済オンライン](https://toyokeizai.net/articles/-/683010))

---

### 🔵 シチュエーション①：謝罪

**目標：「誠意は伝わるが、過度な土下座にならない」絶妙な謝罪バランス**

| フェーズ | 表現 | 使うべき深刻度 |
|---|---|---|
| **軽微な謝罪** | `ご迷惑をおかけし、大変失礼いたしました` | 返信遅れ・軽微なミス |
| **中程度の謝罪** | `ご不快な思いをおかけしてしまい、誠に申し訳ございません` | 対応漏れ・品質問題 |
| **重大な謝罪** | `謹んでお詫び申し上げます。このような事態を引き起こし、申し開きのできないことでございます` | 契約違反・重大障害 |
| **全体謝罪（組織として）** | `このたびのことは、関係者一同猛省しております。近日中に改めてご説明にうかがいたいと存じます` | クレーム・損害発生 |
| **暫定謝罪（調査中）** | `現在原因を確認中です。ご心配をおかけして大変申し訳ありません。〇時までに改めてご報告いたします` | 状況不明時の一次回答 |

**⚠️ 謝罪のNG：再発防止の「抽象的誓い」を単独で使わない**
```
❌「今後はこのようなことのないよう努めてまいります」（だけで終わる）
✅「原因：〜 / 再発防止策：〜 / 次のアクション：〇月〇日までに〜」
```

### 🟠 シチュエーション②：断り（提案・依頼の辞退）

**目標：「今回はNoだが、関係は継続する」を同時に伝える**

| パターン | クッション言葉 ＋ 断り ＋ 関係維持フレーズ |
|---|---|
| **完全辞退** | `せっかくのご提案をいただきながら大変恐縮ですが、今回はご遠慮申し上げます。またの機会にぜひよろしくお願いいたします。` |
| **条件付き辞退** | `誠にありがたいお話ですが、現状の弊社の体制では〇〇が難しい状況です。〇月以降であれば改めて検討できる可能性がございます。` |
| **予算・リソース理由** | `願ってもない機会ではございますが、今期は予算の都合上お引き受けが叶いません。来期以降に向けてぜひ継続してご相談させてください。` |
| **上席判断待ち** | `検討を重ねましたが、現時点ではご要望に添いかねる状況です。いただいた内容は引き続き社内で検討いたします。` |
| **価格面での辞退** | `ご提案の内容は非常に魅力的ですが、弊社の予算感と合致しないため、今回は見送らせていただきます。` |

**✅ 断りメールの黄金構造**
```
①感謝（ご提案・お時間への謝意）
②クッション（残念・心苦しい気持ちの表明）
③断り（明確に、でも柔らかく）
④理由（簡潔に、詳細は不要）
⑤関係維持（「また機会があれば」「引き続きよろしく」）
```

### 🔴 シチュエーション③：督促（入金遅れ・未回答・納期遅延）

**目標：「急かしているが、相手を責めてない」 ── 毅然 × 配慮の両立**

| 督促ステージ | フレーズ | トーン |
|---|---|---|
| **1次督促（ソフト）** | `〇〇の件ですが、その後いかがでしょうか。何かご不明な点がございましたらお気軽にお知らせください。` | 確認ベース |
| **2次督促（丁寧）** | `急かすようで誠に恐れ入りますが、〇〇についてご確認いただけますと幸いです。行き違いの場合はご容赦ください。` | 相手に逃げ道を残す |
| **3次督促（明確）** | `いろいろご事情もおありかと存じますが、〇月〇日までにご回答をいただけますよう、よろしくお願い申し上げます。` | 期限を明示 |
| **最終督促（深刻）** | `大変申し上げにくいのですが、現状のままでは弊社の業務に支障をきたしかねません。〇日（〇曜日）正午までにご連絡いただけますようお願いいたします。` | 深刻さを伝える |
| **入金督促（請求書）** | `ご多忙のところ恐縮ですが、〇月〇日付のご請求について、ご入金の確認が取れておりません。ご確認いただけますでしょうか。万一お手元に届いていない場合はお知らせください。` | 事務的＋丁寧 |

**⚠️ 督促のNG表現**
```
❌「早急にご対応ください」── 命令に聞こえる
❌「何度もお伝えしておりますが」── 責め口調
❌「ご理解いただけているとは思いますが」── 嫌味
✅「お忙しいところ恐れ入りますが」で始めて、期限を具体的に一つだけ示す
```

### 🟣 シチュエーション④：困難な依頼（無理なお願い・スケジュール変更・追加作業）

**目標：「頼みにくいが断られたくない」状況で相手に選択権を与えながら実質的にYESを引き出す**

| 依頼タイプ | 黄金フレーズ |
|---|---|
| **急な依頼** | `突然のお願いで大変恐れ入りますが、もし〇〇が可能でしたら、ぜひご協力いただけますと幸いです。難しいようでしたら、その旨お知らせいただけますか。` |
| **スケジュール変更** | `急な変更をお願いすることとなり、誠に申し訳ありません。〇日か〇日で調整できる可能性はありますでしょうか。ご都合をお知らせいただければ幸いです。` |
| **追加作業の依頼** | `当初のご依頼の範囲を超えるお願いとなってしまい、大変恐縮です。ご対応が可能かどうか、まずはご確認いただけますでしょうか。` |
| **値引き交渉（発注者側）** | `ご負担をおかけすることを十分承知した上で、予算の関係から一点ご相談させていただきたい点がございます。ご無理のない範囲でお聞きいただけますと幸いです。` |
| **無理な納期短縮** | `大変急なお願いで恐縮ですが、事情が事情でございますので、何卒ご検討いただけましたら幸いです。難しい場合は代替案をご提示いただけますと助かります。` |

## 3. 【チャットツール特有の文化】メール vs Slack/Teams/Chatwork

> 「チャットはメールと違い、やり取りのテンポが速くなりがちなため、1メッセージ1トピックで簡潔に伝えることが理想」
> ── [ACEWEB 令和の新ビジネスマナー](https://aceweb.jp/column/reiwa_business_manners/)

---

### 📊 メール vs チャット：構成ルール比較表

| 要素 | **📧 ビジネスメール** | **💬 Slack / Teams / Chatwork** |
|---|---|---|
| **冒頭挨拶** | 必須：`平素よりお世話になっております`系 | **不要**（その日最初の1回だけ、チームにより省略推奨） |
| **宛名** | 必須：`〇〇株式会社 〇〇様` | `@メンション` で代替。「さん付け」も任意 |
| **結論の位置** | PREP法（冒頭に結論、後に理由）が推奨 | **必ず冒頭1行目** に結論・目的を書く（スマホ通知対応） |
| **1メッセージの長さ** | 400〜800字が一般的 | **1スクロール以内**（目安150字以下）。長ければ分割投稿 |
| **改行ルール** | 読点ごとに改行してよい | **意味のある段落ごとにのみ改行**。1文内の改行は不要 |
| **署名** | 必須（会社名・役職・連絡先） | 不要（プロフィールで確認可能） |
| **絵文字・スタンプ** | 基本的に不可（外部向け） | 積極活用推奨：`👍✅👀`等でリアクション |
| **返信期待時間** | 半日〜1営業日 | **即時〜数時間以内**（即答困難なら一次リアクション必須） |
| **保存・記録性** | 件名で整理・フォルダ管理 | チャンネル・スレッド・検索で管理 |
| **フォーマル度** | 高（外部向け契約・正式通知に使用） | 低〜中（社内の日常業務に最適） |

---

### 📐 チャット文体の「5つの構造ルール」

```
【Rule 1】 1メッセージ = 1トピック
  NG：「〇〇の件と、あと△△も確認お願いします。それと☆☆のMTGの件も〜」
  OK：別々に投稿するか、箇条書きで明確に番号を振る

【Rule 2】 冒頭に「種別タグ」を付ける
  【確認】 〇〇の件、承認いただけますか？
  【共有】 先方から返答がありました。
  【依頼】 〇日までに資料の確認をお願いします。
  【緊急】 システム障害が発生しています。

【Rule 3】 改行は「読点ごと」ではなく「意味のまとまりごと」
  NG：「昨日の件ですが、
      先方が確認して、
      折り返すとのことで、
      お待ちの状態です。」
  OK：「昨日の件、先方が確認中で折り返し待ちです。」

【Rule 4】 返信できない時の「一次リアクション」が必須マナー
  「確認中です」「16時までに返します」「👀」（見たスタンプ）

【Rule 5】 @channelと@hereの乱用禁止
  @channel：全員通知（休日・オフライン含む） → 緊急のみ
  @here   ：オンラインのみ通知 → 業務中の周知
  @個人名  ：アクションが必要な相手のみ
```

### 🔎 ツール別：日本企業3種の文化差異

| ツール | 主な利用層 | 特有文化 | AIが生成する際の調整ポイント |
|---|---|---|---|
| **Slack** | IT・スタートアップ・外資系 | 挨拶省略が標準、スレッド返信必須、絵文字リアクションが業務報告の代替 | 最も短く、タグ必須、日本語でも英語的な直球表現OK |
| **Microsoft Teams** | 大手企業・製造業・官公庁 | やや丁寧な文体が残る。メールに近い敬語使用も多い | 挨拶1行は許容。ただし長文はNG |
| **Chatwork** | 中小企業・国内ベンダー | 社外との連絡に使う企業も多い。メールマナーが混入しがち | 社内→省略OK、社外→1行挨拶を入れる |

---

### 🚫 チャットで「メール化」するNG行動（令和版マナー違反）

- `お世話になっております。〇〇株式会社の△△です。` → Slackの社内チャンネルでこれをやると「古い」と思われる
- 既読確認のための連続投稿・即レス催促 → 精神的プレッシャーを与えるNG行為([Chatwork公式](https://go.chatwork.com/ja/column/business_chat/business-chat-594.html))
- 業務連絡をDM（ダイレクトメッセージ）でのみ行う → 情報が属人化し、チームの透明性が下がる
- 1メッセージに500文字超の長文 → 読まれない・対応漏れの原因

<a name="section4"></a>
## 4. 【法的リスク回避】AIが生成してはいけないグレーゾーンキーワード

---

### ⚖️ 4-1：取適法（旧下請法）── 2026年1月改正施行

> 「2026年1月から下請法は『取適法』へ。協議に応じない一方的な代金決定が新たに禁止」
> ── [政府広報オンライン](https://www.gov-online.go.jp/article/202511/entry-9983.html)

#### 🔴 絶対に使ってはいけないフレーズ（取適法違反リスク 高）

| NG表現・状況 | 該当する禁止行為 | リスクレベル |
|---|---|---|
| `弊社の予算の都合で、今月中に〇%値下げをお願いしたい` | **買いたたき**（一方的な代金減額） | 🔴 HIGH |
| `同品質のものが海外では〇割安いので、それに合わせてもらいたい` | 買いたたき（不当比較による値引き強要） | 🔴 HIGH |
| `発注済みですが、コスト削減のためもう少し価格を調整してください` | **発注後の減額要求**（代金減額の禁止） | 🔴 HIGH |
| `今後の取引継続は、この条件を飲んでもらえるかどうかにかかっています` | 優越的地位の濫用（取引停止を示唆した強要） | 🔴 HIGH |
| `消費税分は弊社で負担できません（免税事業者への支払）` | **消費税相当額の不払い** | 🔴 HIGH |
| `値上げの話であれば対応できません` | **協議に応じない一方的な代金決定**（2026年新設禁止） | 🔴 HIGH |
| `協賛金として〇万円ご負担いただけますか` | **不当な経済的利益の提供要請** | 🟠 MEDIUM-HIGH |
| `作業の一部をサービスでやってもらえますか` | 不当な役務提供の要請 | 🟠 MEDIUM-HIGH |
| `前払いでお支払いいただく必要があります（原材料費）` | 有償支給原材料の早期代金回収 | 🟠 MEDIUM |

#### 🟡 グレーゾーン表現（文脈によってはOK、一方的・強要的な場合はNG）

```
「コスト削減にご協力いただければ幸いです」
→ ✅ 相談ベースで合意形成を目指す場合はOK
→ ❌ 毎期当然のように要求する場合は買いたたきの疑い

「他社では〇円でできると聞いています」
→ ✅ 情報共有として伝える場合はOK
→ ❌ 値下げを強要する材料として使う場合はNG
```

---

### 🛒 4-2：景品表示法・薬機法 ── 優良誤認・有利誤認表現

> 「知らずに使った"何気ない一言"が法令違反とみなされるケースが後を絶ちません」
> ── [adrim 広告NGワード集](https://adrim.co.jp/adma/ad-copy-ng-words-risky-expressions/)

#### 🔴 営業メール・提案書で使ってはいけないキーワード一覧

**● 効果・品質の過大表現（優良誤認表示）**

| NG表現 | 問題 | 代替表現 |
|---|---|---|
| `導入すれば必ず〇〇が改善します` | 断定的効果保証→景表法違反 | `導入企業の〇%が改善を実感（調査期間・対象明記）` |
| `業界No.1` / `日本一` | 根拠・調査機関・調査対象の明示なし | `〇〇調査（〇年）において〇〇部門No.1（調査概要URL付き）` |
| `満足度100%保証` | 測定不可能な断定 | `〇〇調査において満足度94.2%（n=〇〇）` |
| `すべての課題を解決します` | 過大な能力保証 | `〇〇の課題に有効な機能を提供しています` |
| `売上が〇倍になります` | 根拠なき数値保証 | `導入事例では売上〇%向上（〇社・〇ヶ月間）のケースがあります` |
| `競合他社より圧倒的に優れています` | 不当比較表示 | `〇〇機能において、独自の強みを持っています` |

**● 価格・割引の有利誤認表示**

| NG表現 | 問題 |
|---|---|
| `今だけ50%OFF！`（実際は常時この価格） | 有利誤認表示：「今だけ」が虚偽 |
| `限定10社様のみ`（根拠なし） | 限定性の虚偽 |
| `最安値保証`（比較根拠なし） | 有利誤認：根拠が必要 |
| `通常価格〇円のところ〇円`（通常価格が架空） | 二重価格問題 |

**● ステルスマーケティング（2023年景表法改正で規制）**

```
❌ 「弊社製品の利用者から自然に集まったレビューです」
   → 実際はインセンティブ付きレビューの場合は違反

❌ 「お客様の声」として第三者風に書かれた営業文
   → 実際は社員・関係者の場合は違反
```

---

### 🏥 4-3：医療・健康系コンテンツの特別注意キーワード（薬機法）

```
絶対NG：「治る」「治癒」「効果が出る」「完治」「副作用ゼロ」「安全性が証明」
要注意：「改善をサポート」（根拠なしで使用すると問題）「健康に良い」（医薬品的表現）
```

<a name="section5"></a>
## 5. 【AI内部判定フレームワーク】生成前チェックリスト

**箇条書きメモを受け取ったAIが、文章生成前に必ず通るべき5段階の判定プロセス**

---

### 🧠 STEP 1：受信者の属性判定

```
判定変数：
  相手の役職      → [経営者 / 決裁者 / 担当者 / 現場 / 不明]
  自社/相手の規模  → [大企業 / 中小企業 / 個人事業主 / スタートアップ]
  関係値         → [初回接触 / 取引1年未満 / 長期パートナー / 社内]
  年齢層推定      → [〜30代 / 40代〜50代 / 60代〜]
  ITリテラシー    → [高 / 中 / 低（メール主体）]

出力への影響：
  ・経営者 × 初回 → 敬語強め・簡潔・格式高め
  ・担当者 × 長期 → やや砕けた丁寧語・個人名を入れる
  ・社内 × Slack  → 挨拶省略・タグ必須・150字以内
```

---

### 🧠 STEP 2：感情・心理状態の判定

```
推定すべき相手の感情状態：
  [通常] → 標準的な敬語・構成でOK
  [困惑・クレーム気味] → クッション言葉を厚くする。共感ファースト
  [急いでいる / 忙しい] → 冒頭1行で結論。詳細はリンク・添付へ
  [怒っている可能性] → 謝罪ファースト。言い訳は後。原因→対策の順
  [断った後] → 感謝ファースト。次の機会への言及で関係維持

生成ルール：
  ・感情が高ぶっていそうな相手への文章には「断定表現」を使わない
  ・督促メールは相手に「逃げ道（行き違いの可能性）」を必ず残す
```

---

### 🧠 STEP 3：コミュニケーション種別判定

```
種別フロー：

  箇条書きメモを受信
       ↓
  ① ツール判定
      → メール / Slack / Teams / Chatwork / 手紙 / チャット
       ↓
  ② 内外判定
      → 社内（インフォーマル可）/ 社外（フォーマル必須）
       ↓
  ③ 方向性判定
      → 送信 / 返信 / 転送 / CC対応
       ↓
  ④ トーン設定
      → [格式高] / [標準ビジネス] / [丁寧カジュアル] / [チャット]
```

---

### 🧠 STEP 4：法的リスクスキャン

```
生成前に以下のキーワードが箇条書きに含まれていないか確認：

  ⛔ 取適法リスクワード：
     「値引き」「コスト削減」「単価調整」「価格を下げて」
     「発注後の変更」「消費税」「支払い条件の変更」
     → 含まれている場合：一方的・強要的でない表現に書き換え

  ⛔ 景表法リスクワード：
     「No.1」「必ず」「100%」「全員」「最安値」「今だけ」
     「日本一」「業界最高」「絶対」「確実に」「証明された」
     → 含まれている場合：根拠明示or削除を促すアラートを出力

  ⛔ 薬機法リスクワード（医療・健康系のみ）：
     「治る」「治癒」「副作用なし」「安全」「効果が出る」
```

---

### 🧠 STEP 5：文体チェック（ChatGPT構文フィルター）

```
生成後に以下のセルフチェックを実施：

  □ 「平素より大変お世話になっております」で始まっていないか
  □ 「させていただく」が3回以上連続していないか
  □ 「なお」「また」「つきましては」が1通に2回以上ないか
  □ 「ご共有」「アップデート」「フォローアップ」の直訳語がないか
  □ 謝罪文が「抽象的な誓い」だけで終わっていないか
  □ 「何卒ご理解ご協力のほど〜」が感情なしに使われていないか
  □ クッション言葉が1個もない（冷たすぎる）か
  □ クッション言葉が多すぎて要件が埋もれていないか（過剰ソフト化）
  □ 「以上、よろしくお願いいたします」で唐突に終わっていないか

→ 1つでも✅がついた場合、該当箇所を書き換えてから出力
```

---

## 📎 補足：AI生成文の「人間化」最終仕上げ3ルール

```
① 具体性を入れる
  ❌「先日はありがとうございました」
  ✅「先日は〇〇の件でお時間をいただき、ありがとうございました」
     → 固有名詞・日時・内容を入れるだけで人間らしさが増す

② 感情ワードを1語入れる
  ❌「ご連絡申し上げます」
  ✅「ご連絡が遅くなり、大変失礼いたしました」
     → 感情（心苦しい、嬉しい、残念、安心）を1語加えるだけで温度が上がる

③ 相手の名前を本文中に1回使う
  ❌「ご確認いただければ幸いです」
  ✅「〇〇様にご確認いただければ大変助かります」
     → 宛名が「あなたに向けて書かれた文章」に変わる
```
